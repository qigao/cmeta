# Experimental CNet SCTP — pure C11

Independent RFC-first protocol workstream for [Salts #1181](https://github.com/qigao/salts/issues/1181) and upstream prerequisite for [TurboMedia #227](https://github.com/qigao/turbomedia/issues/227).

**Research only. This is not a complete SCTP engine, not authenticated production transport and not WebRTC-interoperable yet.** No Rust/C++ protocol source, FFI or runtime is involved. No production CNet or TurboMedia target uses these objects.

## Isolation and build

This directory is a self-contained C11 CMake project, not a subdirectory of the production Salts CMake graph. Its only installed/exported test package target is `CNetSctpPrototype::Wire`. The new M2 `cnet_sctp_assoc_proto` target, `src/sctp_assoc_internal.h` and its tests are **private** and NOT installed or included in `SaltsTargets`.

```sh
cmake -S cnet/sctp -B build-cnet-sctp -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-cnet-sctp --config Release
ctest --test-dir build-cnet-sctp -C Release --output-on-failure
cmake --install build-cnet-sctp --config Release --prefix "$PWD/sdk-cnet-sctp"
cmake -S cnet/sctp/tests/installed -B build-cnet-sctp-consumer \
  -DCMAKE_PREFIX_PATH="$PWD/sdk-cnet-sctp"
cmake --build build-cnet-sctp-consumer --config Release
ctest --test-dir build-cnet-sctp-consumer -C Release --output-on-failure
```

## Implemented slices

- **M1 wire:** sync, bounded, allocation-free RFC 9260 common header / Chunk framing, Castagnoli CRC32C, basic INIT validation and full packet validation before borrowed views. Borrowed views are valid only while the caller retains packet bytes. Association semantics, unknown chunk reporting and extension negotiation are not implemented by this decoder.
- **M2 research handshake:** four-message INIT / INIT ACK / COOKIE ECHO / COOKIE ACK state transitions; explicit caller-provided monotonic clock, bounded T1-init/T1-cookie retransmit and timeout, capacity-before-state-change checks, fixed-size packet storage, one Owner verifier, stop/drain/destroy. Closed-side INIT ACK remains stateless until cookie validation; late duplicate COOKIE ECHO re-ACK does not re-open. Signed cookie claims include SCTP ports, tags, initial TSNs, stream/window parameters, creation time and a caller-supplied **opaque non-pointer DTLS peer-generation binding**.
- **M2 secure initialization:** the Association no longer takes caller-defined Verification Tag / Initial TSN values. A **required** C11 entropy callback generates 8 bytes under the Owner; missing, failed, zero-tag or reentrant initialization is explicitly rejected. Deterministic entropy in baseline unit tests is a **non-cryptographic fixture only**. The optional Linux GmSSL job invokes the real OS-backed `rand_bytes` C API for Tag/TSN generation; complete cross-platform provider/Owner integration and uniqueness across peer generations are still OPEN.
- **M2 HMAC and bounded rotation:** a required MAC signing and separate MAC verification callback allow a *private, test-only* two-key ring (current plus one prior epoch). GmSSL SM3-HMAC uses protocol-version domain separation and 32-byte owner-controlled secrets; both candidates are checked without early success, third-generation rotation fails until explicit prior-key retirement, and retired key bytes are wiped. Tests exercise actual in-flight Cookie completion across rotation, forgery/wrong-key/DTLS-Generation rejection and key retirement. These pass only the isolated crypto boundary: no auto-rotation/expiry, no actual CNet ComponentPlugin lease/drain barrier and no browser interoperability. **GmSSL and Association are not exported in the installed Wire SDK.**

- **M2 INIT/INIT ACK parameter reporting:** a separate allocation-free private C11 parser validates TLV lengths, padding, unique/mandatory State Cookie and a 128-TLV ceiling before Cookie signing or Association transitions. RFC 9260 unknown-parameter actions **00 stop, 01 stop+report, 10 skip and 11 skip+report** are implemented within a fixed **8-report / 512-byte** limit; excess reports fail closed without truncation. On INIT, 01/11 reports are copied into Type-8 *Unrecognized Parameter* fields of INIT ACK; on INIT ACK, they generate ERROR cause 8 bundled with COOKIE ECHO. Incoming bundled ERROR is strictly checked before admitting COOKIE ECHO; diagnostics are not yet surfaced to the ULP. All reporting is synchronous, with no retained views, heap allocation or asynchronous delivery.
- **M2 Host Name ABORT:** valid INIT or INIT ACK containing deprecated Host Name Address causes a 16-byte ABORT with the correct peer Initiate Tag and T-bit=0, without optional cause. A rejected 15-byte output capacity does not sign or transition the Association. INIT ACK ABORT seals the local handshake. Malformed mandatory fields and other known unsupported IPv4/IPv6, ECN, Cookie Preservative and Supported Address Types remain rejected in this **single-path experimental profile**; full ABORT causes, restart/tie-tag state, mixed unknown-plus-recognized Chunk bundles and full RFC packet-level action/transaction conformance remain open. The private Association implements a bounded subset for a single unrecognized Chunk and packets consisting only of unrecognized Chunks, with ordered stop/skip, cause-6 reporting and capacity atomicity; this is not complete unknown-Chunk conformance or browser interoperability. End-to-end CRC-correct INIT/COOKIE/ERROR/ABORT tests and 10,000 deterministic TLV mutations exercise the boundary.

- **M2 duplicate-Cookie and RFC Table 12 design gate:** when an authenticated COOKIE ECHO exactly matches both Verification Tags and the peer Initial TSN of an already ESTABLISHED Association, the research engine can re-ACK it after its original Cookie TTL (RFC 9260 §5.2.4). Expired cookies with different peer identities remain rejected; Stop prevents re-opening. A separate pure C11 **decision-only** Table 12 classifier covers Cases A (restart), B (simultaneous-open collision), C (stale Cookie) and D (duplicate ACK), plus unrecognized combinations. **Case A/B decisions are NOT wired to live state transitions**: they require Tie-Tag-validated MAC claims, CNet Owner/DTLS Generation admission, Lease/Drain, peer-tag commit and timer handling before any production restart is allowed. No new TCB can be created or replaced by this classifier.

- **M2 bounded simultaneous-open handshake (not restart):** an authenticated INIT received during `COOKIE-WAIT` or `COOKIE-ECHOED` can generate INIT ACK using the original local Tag/TSN, without overwriting the saved INIT/COOKIE ECHO, stopping T1, creating another TCB or changing peer identity. A later MAC-verified COOKIE ECHO can complete Table 12 case B while still in `COOKIE-WAIT` (peer Tag unknown) or case D in `COOKIE-ECHOED` when the preexisting peer Tag and Initial TSN match. The complete COOKIE ACK is admitted **before** the Owner commits peer identity and clears T1. No partial buffer acceptance, automatic retry, hidden worker or fallback is introduced. Both peers initiating concurrently, late INIT, duplicate COOKIE ACK, output-capacity failure, and a re-MACed wrong-peer Cookie with a valid checksum have deterministic regression tests.
- **Critical remaining RFC boundary:** the private `SC11` Cookie format does not yet encode authenticated restart Tie-Tags. This makes the `COOKIE-ECHOED` reply a **restricted experimental subset**, not full §5.2.1/§5.2.2 compatibility. Existing `ESTABLISHED` associations still reject an unexpected INIT or MAC-verified peer replacement rather than run a premature restart. Case A and any Case B involving an existing different peer are **blocked** until generation-bound Tie-Tags, explicit CNet Owner/DTLS leases, atomic restart/admission, ULP notifications and sanitizer gates exist.

- **M2/M3 bounded DATA/SACK/T3 path:** a private C11 DATA engine shares the established Association's Owner, verified tags, per-stream sequence state, initial TSNs, cwnd and advertised receive window. It provides ordered/unordered single-fragment delivery, wraparound TSN and Gap SACK validation, duplicate rejection, bounded T3 virtual-clock retransmission, 16 TX tickets and 32 RX slots. A **single owner-copied 24 KiB queued message** can be emitted through explicit one-packet-at-a-time `queue/pump`. Unnegotiated associations use legacy DATA/SSN; negotiated RFC 8260 associations use I-DATA with independent ordered/unordered MID counters and FSN reassembly across non-contiguous TSNs. No data message is delivered before a complete B→E sequence. Tests exercise a 20 KiB post-handshake round trip, cross-stream interleaved receive, plus queue/receive-buffer capacity and full-source sanitizer gates. **This is not yet full RFC 9260 congestion/rwnd/T3/Fast Retransmit/restart/PMTU conformance; the sender remains a one-active-message FCFS scheduler and no partial delivery is available.**
- **M2 RFC 9260 loss and window recovery (private, bounded):** retained revocable Gap ACKs, actual Flight Size distinct from pending retransmission intent, earliest-outstanding T3, multi-TSN Fast Recovery, single loss-epoch cwnd reduction, gap reneging, bounded RTO/RTT and retransmit-budget guards. RFC 9260 §6.1(C) priority is enforced at the common direct DATA / fragment-pump admission point: callers receive `RETRANSMIT_PENDING` and run Owner-driven `advance()` first. A peer zero advertised receive window allows one explicitly scheduled, single-byte DATA probe from the copied message queue after one RTO, with bounded exponential backoff and no automatic new worker. A responsive closed-window peer does not count as transport failure; a silent peer has a bounded terminal. The receiver drops over-window DATA but sends a zero-window SACK; after `take()` frees RX slots, the Owner can emit one window-update SACK through the private Association. The tests include lost-first-fragment recovery, zero-window retry/timeout, Karn RTT exclusion, 16-ticket/32-slot pressure, reopened-window DATA, exact CRC wire paths and atomic capacity refusal. This is **not** complete congestion, PMTU, all outbound bundling modes or browser qualification.
- **M2 RFC 9260 §9 graceful close (private):** SHUTDOWN-PENDING waits for all cumulative TX acknowledgements; SHUTDOWN carries peer cumulative TSN and T2 retransmissions refresh it after late DATA. SHUTDOWN-RECEIVED waits for remaining sender DATA, SHUTDOWN-SENT and SHUTDOWN-ACK-SENT retransmit bounded control chunks, and simultaneous SHUTDOWN is handled. SHUTDOWN ACK/COMPLETE enforce verification tags and capacity-before-commit. The fixed RX records survive terminal wire close until the original Owner retrieves ULP messages; `drained()` and `destroy()` refuse early completion. A forced `stop()` is explicitly abortive. T2 currently uses the private Owner's configured bounded handshake RTO profile; an optional absolute T5 guard emits ABORT when its deadline expires and is tested against late ACK and unknown-Chunk input. Independent SCTP shutdown interoperability and complete exception paths remain open.
- **M2 RFC 9260 §6.9/§6.10 receive bundling (private):** admits multiple CRC-correct legacy DATA chunks and a single leading SACK under a 1280-byte peer-ingress bound, processing a copied bounded state and emitting one cumulative SACK. Local egress and retained controls remain capped at 1200 bytes. A malformed trailing DATA or insufficient output capacity rolls back all earlier chunk effects. Outbound aggregation and general mixed control bundling remain separate gates.
- **M3 RFC 3758 / RFC 8260 PR-SCTP (private, bounded):** INIT/INIT ACK advertise and parse the dedicated `Forward-TSN-Supported` parameter (`0xC000`) plus I-DATA/I-FORWARD-TSN chunk support. Direct sends and the copied 24 KiB `queue/pump` path accept reliable, timed-lifetime, or maximum-retransmit policies. When any fragment reaches its policy, RFC 3758 §3.5 A3 is applied transactionally to every assigned DATA/I-DATA TSN in that message and to its copied unsent suffix. One of 16 fixed Owner-pulled records reports the SID, PPID, SSN/MID, full message size, assigned TSN range, policy and reason; PR-message admission reserves bounded event capacity, short FORWARD-TSN output commits neither abandonment nor an event, and an unsent timed message expires without consuming TSN/SSN/MID. The Owner preserves RFC congestion response when loss triggered abandonment, emits and retransmits one retained FORWARD-TSN variant, advances the receiver cumulative TSN through already received gaps, skips ordered SSNs or ordered/unordered MIDs, discards affected incomplete reassembly, and never releases a received complete later message merely because its TSN was forwarded across. DCEP channel types now project to the same shared private DATA reliability value, with RFC 8832 pre-ACK ordered-send and user-DATA handshake rules. Legacy DATA and negotiated I-DATA fragmented tests cover Gap-ACKed siblings, unsent suffix cancellation, next-message sequence reuse rules, exact-once events, negotiation, malformed/duplicate input, SACK settlement and shutdown drain. Independent peer partial-reliability interoperability remains open.
- **M3 WebRTC profile:** private RFC 8832 DCEP OPEN/ACK codec with DTLS-role SID parity, bounded UTF-8 labels and reliable/ordered PPID 50 control messages; OPEN/ACK has been carried through actual post-Cookie SCTP DATA/SACK tests. RFC 8831 user payload PPID 51/53 and PPID 56/57 empty text/binary (one zero wire byte, zero logical length) are supported by a private stateless adapter and verified through the Association. A bounded RFC 6525 slice now negotiates RE-CONFIG with RFC 5061 Supported Extensions, sends one outgoing-SID reset only after retained DATA drains, blocks that SID until the peer's reciprocal reset, retransmits on the Owner clock with bounded RTO backoff, replays duplicate request responses, resets SSNs and reports Owner-pulled completion before SID reuse. A performed peer outgoing reset automatically schedules the corresponding drained outgoing reset; same-SID simultaneous close is consumed without a reset loop, and an uncertain timeout retains the exact request for explicit retry. Incoming resets support one fixed deferred `In progress` transaction: affected post-barrier DATA remains in bounded RX storage but is withheld from ULP delivery until cumulative receipt and pre-barrier delivery permit a capacity-atomic final response/reset. A received Incoming SSN Reset accepts one, multiple or the empty all-stream list and schedules the required list-preserving corresponding Outgoing Reset immediately or after active reset/DATA/unread-event conflicts clear. A locally initiated Incoming Reset uses the same bounded timer slot, supports explicit multi-SID and empty all-stream encoding, remains independent of local outbound DATA, and completes through a matching peer Outgoing Reset, denial or timeout Owner event; a matching deferred TSN barrier keeps only fixed correlation state and does not create a reciprocal loop. Received `Outgoing+Incoming` and `Response+Outgoing` two-parameter chunks are staged atomically; the immediate reciprocal response is retained and retransmitted as the RFC-allowed `Response+Outgoing` pair. The private Owner can also initiate the Appendix A paired bidirectional form for explicit SIDs or both all-stream directions: one retained packet/timer/retry budget owns two independently completed halves, short output capacity commits no state, and timeout reports only unfinished directions. Add Outgoing, Add Incoming and paired Add Streams now grow the live DATA stream range only after the required positive completion, accept peer growth within the fixed 16-stream profile, initialize new SSNs at zero, replay duplicates, and report bounded Owner-pulled stream-change snapshots. Add Incoming success is correlated by the peer's corresponding Add Outgoing request rather than an unsafe direct success Response. For a received pair, the immediate Add Outgoing Response is emitted first and `advance()` publishes the separately retained corresponding request, avoiding a parameter combination RFC 6525 does not permit; the two local halves complete independently but produce one final snapshot. SSN/TSN Reset now freezes new DATA assignment, requires both fixed DATA directions to be quiescent, exchanges the mandatory 20-byte response TSN pair, rebases both TSN spaces and all SSNs atomically, replays duplicates and reports one Owner-pulled association-reset snapshot. New local requests observe the RFC 6525 30-second minimum interval from the original transmission (retries do not extend it); simultaneous local requests consume both peer sequence numbers with `Request already in progress`, preserve both TSN spaces, and can retry after that interval. Retained or unread DATA produces `In progress`/`BUSY` instead of being abandoned or silently discarded; congestion and RTT state remain owned by the existing DATA TCB. Complete browser interoperability remains OPEN.

Every protocol entry point is synchronous and requires caller-provided Owner admission. No worker, independent UDP endpoint, process-global timer, retained external packet view, automatic application retry or raw runtime-object persistence was added.

The regular C11 package/test build has **no GmSSL dependency**. The gated
`-DCNET_SCTP_TEST_GMSSL=ON` option builds only the private test target
`cnet_sctp_gmssl_mac_test`, using `find_package(GmSSL CONFIG REQUIRED)`;

and the vcpkg baseline to `b1b19307e2d2ec1eefbdb7ea069de7d4bcd31f01`.
The observed Linux binary was `gmssl:x64-linux@3.2.0#9` (Apache-2.0).
It runs source-instrumented ASan/UBSan tests separately from a **clean Release**
installed C11 consumer and checks that GmSSL/Association internals do not ship.
A real MAC test is not a certification of the full association or its key/owner
lifetime under concurrent cancellation.

## Gaps that block production

The prototype handles a bounded handshake, DATA/I-DATA/SACK/T3/Fast Recovery/flow-control subset, graceful SHUTDOWN/T2, private bundling, fragmented timed/max-retransmit PR-SCTP with the negotiated FORWARD-TSN variant and bounded Owner-pulled abandonment records, DCEP channel-to-DATA policy projection/PPID and the constrained RFC 6525 slice above. It does **not** yet provide complete RFC 9260 congestion/PMTU/multipath or every retransmission/receiver-window edge case, complete restart/tie-tag and every shutdown/abort exception, production cookie-key lifetime/rotation admission, AUTH/ASCONF, multi-message sender scheduling/partial delivery, complete RFC 6525 collision/ULP semantics or independent browser compatibility. All gaps are tracked in [RFC_MATRIX.md](RFC_MATRIX.md). A successful self-to-self handshake with a test-only MAC is **not** independent interoperability and is not a security pass.

**Release status: NO-GO.** See [RELEASE_READINESS.md](RELEASE_READINESS.md) for exact 2.3.0/rc.15 ancestry, M0–M6 gaps, installed-SDK qualifications and the separation between Salts.Native stable release and this non-production prototype.

The private research baseline from [PR #1281](https://github.com/qigao/salts/pull/1281)
is merged on `master`; that merge did not publish a session SDK or authorize a
production cutover. Preserve production CNet, TurboMedia/usrsctp and the
published SDK until the remaining release gates pass.

### Experimental peer ABORT reason retrieval (private)

The C11 Association prototype retains one bounded, owned peer-ABORT terminal event for the existing Owner to pull with `cnet_sctp_assoc_take_peer_abort()`. The event includes optional RFC 9260 User-Initiated Abort Cause 12 reason bytes (up to the private 1180-byte limit), and pre-teardown TSN summary if DATA was established. The event is consumed exactly once; capacity failure is retryable without mutation; `stop()` explicitly discards it. No callbacks, borrowed wire pointers, worker or production SDK export are introduced. This is not full ULP integration or interop qualification.
