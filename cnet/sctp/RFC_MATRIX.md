## Unknown Chunk handling contract (RFC 9260 §3.2, §3.3.10.6)

The wire module's top-two-bit helper is only an action-bit decoder; it is **not** an unknown-chunk policy. The association must first decide whether a Chunk Type is recognized by this implementation (including distinguishing recognized-but-unimplemented standard/extension types from genuinely unknown values), then apply the action bits only to genuinely unrecognized types.

Bounded private behavior: single unrecognized Chunk and unknown-only packets use the four action bits in packet order, stop at the first stop-action, and currently copy the complete offending Chunk TLV into cause 6 for REPORT actions. The encoded response is staged under the private 1200-byte packet limit; too-small output or oversize report refuses admission without changing output or the time watermark. The Wire parser caps packets at 128 chunks, and the unknown-only fast path now rejects pre-COOKIE association states rather than emitting an ERROR using a missing Peer Tag. The absolute T5 guard takes precedence for otherwise admissible packets. Mixed unknown-plus-recognized bundles remain fail-closed. **These are bounded implementation contracts, not a full RFC/OOTB interop claim.** Full-conformance requirements remain open:

- `00`: stop processing this packet and discard this chunk plus all following chunks; do not dispatch a later DATA/control chunk.
- `01`: same stop behavior, and report the unrecognized chunk with an ERROR cause code 6.
- `10`: skip this chunk and continue examining the remaining packet, subject to the association's packet-wide preflight/transaction rules.
- `11`: skip this chunk, continue, and report it with ERROR cause code 6.
- Cause 6 is a 16-bit code followed by a 16-bit cause length. **This private implementation currently copies the entire offending Chunk (Type, Flags, Length, Value), but this is not a normative RFC requirement proven by these tests.** RFC 9260 §3.3.10.6 explicitly mentions the header fields. [Erratum 8387](https://www.rfc-editor.org/errata/eid8387) proposed requiring the entire Chunk Value; it was **rejected on 2026-02-12**, citing the risk of forcing fragmentation. The proper interoperable, PMTU-bounded representation and independent peer acceptance are **OPEN**. Any emitted ERROR still needs self-consistent cause/Chunk lengths and CRC32C.
- Reporting must not create ERROR-on-ERROR/ABORT loops. Do not emit a partial ERROR or dispatch any later chunk before all framing, verification-tag, bundle-order, output-capacity, and state-commit preconditions are satisfied.
- The private tests cover four actions, several ordering permutations, dense causes, 128/129-Chunk bounds and caller-output capacity, but not the **independent** RFC 9260 legal combination/state matrix, PMTU/error-cause behavior, OOTB response handling (RFC 9260 §8.4), unknown+recognized mixed packets, or malformed-input fuzz. An OOTB reflected-tag ABORT/T-bit path is not implemented and must not be simulated by a zero-tag ERROR. Full Unknown Chunk semantics remain **OPEN** beyond the bounded single/unknown-only subset.

Sources: [RFC 9260 §3.2/§3.3.10.6](https://www.rfc-editor.org/rfc/rfc9260.html#section-3.3.10.6), [RFC 9260 §8.4 OOTB](https://www.rfc-editor.org/rfc/rfc9260.html#section-8.4), and [rejected Erratum 8387](https://www.rfc-editor.org/errata/eid8387). Complete cause Value copying is a current private choice, **not a closed RFC interop gate**.

## ABORT terminal boundary checkpoint (2026-10-22)

The private C11 Association now handles a bounded terminal ABORT packet according to RFC 9260 §§3.3.7, 8.5.1, and 9.1:

- The first ABORT in a packet defines the terminal boundary. The entire packet still must pass CRC32c and Wire framing checks; malformed trailing framing rejects the packet without TCB or clock mutation.
- DATA+ABORT is rejected by the Wire layer. INIT, INIT ACK, and SHUTDOWN COMPLETE remain standalone-only and cannot be bundled with ABORT.
- Before ABORT, only shape-validated controls in this private profile are admitted. Unknown STOP/STOP+REPORT actions stop packet processing; unknown SKIP/SKIP+REPORT actions continue to ABORT without emitting ERROR, because a packet containing ABORT must not trigger a response.
- The ABORT itself must pass its Cause-TLV shape check and T-bit Verification Tag rule. A valid ABORT terminates locally and silently before packet-triggered T5, even with zero output capacity.
- Chunk semantics after ABORT are ignored. This does **not** bypass full packet framing/CRC validation and does not claim arbitrary registered-control support.

Regression coverage includes SACK+ERROR+ABORT, malformed preceding controls and malformed ABORT Causes at T5, both T-bit modes, unknown action bits before ABORT, semantically malformed HEARTBEAT and unknown STOP+REPORT after ABORT, malformed trailing Chunk Length, and Wire rejection of INIT/INIT ACK/SHUTDOWN COMPLETE bundled with ABORT in both orders.

The implementation is still a **bounded private subset**. Semantic processing/ULP reporting of preceding controls, full OOTB response generation, independent peer interoperability, fuzz/TSan, M3 PR-SCTP/reset/interleaving, and installed-SDK/six-RID qualification remain OPEN. PR #1182 remains Draft/Open; do not merge, publish, release, or cut over.

## Peer-ABORT Owner-pulled ULP event (2026-10-22)

Private C11 SCTP Association now supports an **exactly-once, Owner-pulled** peer-ABORT terminal record (RFC 9260 §§3.3.10.12, 9.1, 11.2.5). This is NOT an installed SDK or production API.

- After complete CRC, Verification Tag (T=0 Local Tag / T=1 nonzero Peer Tag), Chunk/Cause and supported-prefix admission, a peer ABORT still terminates **silently before packet-triggered T5**. It records a terminal event before destroying its DATA TCB.
- The record retains a typed flag indicating peer ABORT even when there is **no Cause 12**, and optionally captures the first User-Initiated Abort Cause 12's **exact bytes**, plus pre-teardown `last_acked_tsn` / `last_sent_tsn` where a DATA TCB exists. It does not persist packet pointers, provider state, locks or threads.
- The private ingress ceiling of 1200 bytes bounds raw reason bytes to **1180** (12-byte common header + 4-byte ABORT + 4-byte Cause header). No truncation or unbounded heap. Rejected/malformed packets never publish an event.
- `cnet_sctp_assoc_take_peer_abort()` requires the Owner. Insufficient caller buffer returns CAPACITY without consuming the event or modifying the caller's info/output; a successful take copies the exact reason bytes and clears internal storage. A second take returns EMPTY. Explicit `stop()` discards an unread event and clears its bytes; `destroy()` clears the whole Association.
- Regression tests cover a preceding non-user cause, final unpadded Cause 12, zero-byte Cause-12 absence, exact 1180-byte upper boundary, too-small output retry, terminal no-reply and lifecycle wipe. A real post-COOKIE DATA path also verifies last-ACKed/last-sent TSN capture before the DATA TCB is torn down.

Remaining **OPEN**: callback/ULP integration beyond this private Owner-pull seam, complete preceding-control semantics, actual independent SCTP peer/DTLS/Browser wire oracle, fuzz/TSan, PR-SCTP/reset/interleaving, and installed SDK/six-RID. Passing private C11 tests does not authorize merge, release, publish or production cutover.
